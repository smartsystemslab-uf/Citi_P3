# Migration from the first Task 4 prototype

## Kept

- Five decision types.
- Default deny.
- Role, resource, workflow, risk, time, approval, and obligation policies.
- Front/mid/back-office policy separation.
- Canonical identity/resource configurations generated by the interface package.
- `cache_control: NO_STORE` until Task 5.

## Replaced

| First prototype | Security-hardened rewrite |
|---|---|
| String `subject` trusted from JSON | Canonical/runtime binding plus signed PEP proof |
| Caller-provided risk level | Signed score, verified threshold mapping |
| Caller-provided auth integer | Signed factors, deterministic recalculation |
| Boolean `human_approved` | Signed request-bound approval evidence |
| Caller timestamp for policy time | PDP trusted server time |
| Reusable identical request | Nonce + JTI one-time verification |
| Unsigned YAML policies | Schema-validated Ed25519-signed bundles |
| SHA hash only | Signature plus rollback state |
| Unsigned JSON response | Unchanged body plus signed HTTP headers |
| Local flat audit | Schema-compatible tamper-evident hash chain |

## Compatibility note

The old prototype's simplified string request is intentionally not accepted by
the secure `/v1/authorize` endpoint. The common interface-standard v1.0 request
is the stable supported contract. This is not a schema change; it is alignment
with the interface package already created for the project.
